## 2. Architecture: Why `system_server`?

Why does Android place hundreds of services inside one monolithic Java process (`system_server`) instead of running them as separate Linux daemons?

### The End-to-End Vertical Slice

Here is how an app call travels down to silicon:

```
+-------------------------------------------------------------------+
|                        App Address Space                          |
|  MainActivity -> FooManager.getVersion()                         |
|         |                                                         |
|         v                                                         |
|  IFooManager.Stub.Proxy.getVersion()                              |
+---------|---------------------------------------------------------+
          |  Binder IPC (/dev/binder)
          v
+-------------------------------------------------------------------+
|                     system_server (UID 1000)                      |
|  FooService.FooImpl.getVersion()                                  |
|     - Check permission: enforceCallingOrSelfPermission()          |
|     - Binder.clearCallingIdentity()                               |
|     - Call HAL proxy: mHalService.getVersion()                    |
+---------|---------------------------------------------------------+
          |  Binder IPC (/dev/binder - Treble Seam)
          v
+-------------------------------------------------------------------+
|                   vendor.foo-service (HAL)                        |
|  aid::android::hardware::foo::Foo::getVersion()                   |
|     - Talk to Linux device node: /dev/foo_device                  |
+-------------------------------------------------------------------+
```

## 3. Defining the App-Facing Framework AIDL

Create `frameworks/base/core/java/android/os/IFooService.aidl`. Notice that unlike HAL AIDL, framework AIDL does NOT use `@VintfStability` because it is internal to the `/system` partition:

```aidl
// frameworks/base/core/java/android/os/IFooService.aidl
package android.os;

/**
 * System-internal interface for Foo hardware management.
 * @hide
 */
interface IFooService {
    /**
     * Reads hardware version. Requires android.permission.READ_FOO_HARDWARE.
     */
    int getVersion();

    /**
     * Returns hardware telemetry ping.
     */
    String ping();
}
```

import android.os.Binder;
import android.os.IBinder;
import android.os.IFooService;

public class FooService extends SystemService {

            mImpl.connectToHal();
        }

        private void connectToHal() {
            // Connect to AIDL HAL via libbinder_ndk or Java AIDL stub

            mContext.enforceCallingOrSelfPermission(

            } finally {
                Binder.restoreCallingIdentity(token);
            }
        }

        }
    }

## 5. Registering the Service in `SystemServer.java`

Inside `frameworks/base/services/java/com/android/server/SystemServer.java`, find `startOtherServices()` and register your new service:

    mSystemServiceManager.startService(FooService.class);

## 6. Exposing the Client Manager: `FooManager`

Apps should never invoke raw `IFooService` Binder stubs directly. They use the client manager:

```java
// android/os/FooManager.java
package android.os;

import android.annotation.SystemService;
import android.content.Context;

@SystemService(Context.FOO_SERVICE)
public class FooManager {
    private final Context mContext;
    private final IFooService mService;

    public FooManager(Context context, IFooService service) {
        mContext = context;
        mService = service;
    }

    public int getVersion() {
        try {
            return mService.getVersion();
        } catch (RemoteException e) {
            throw e.rethrowFromSystemServer();
        }
    }
}
```

Register `FooManager` in `frameworks/base/core/java/android/app/SystemServiceRegistry.java`:

```java
registerService(Context.FOO_SERVICE, FooManager.class,
    new CachedServiceFetcher<FooManager>() {
        @Override
        public FooManager createService(ContextImpl ctx) throws ServiceNotFoundException {
            IBinder b = ServiceManager.getServiceOrThrow(Context.FOO_SERVICE);
            return new FooManager(ctx.getOuterContext(), IFooService.Stub.asInterface(b));
        }});
```

## 7. Calling the Service from an App

In a sample Android application (`MainActivity.java`):

```java
package com.example.foodemo;

import android.app.Activity;
import android.os.Bundle;
import android.os.FooManager;
import android.util.Log;

public class MainActivity extends Activity {
    private static final String TAG = "FooDemo";

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        // Access your system service through the standard Context API
        FooManager fooManager = getSystemService(FooManager.class);
        if (fooManager != null) {
            int version = fooManager.getVersion();
            Log.i(TAG, "Foo hardware version: " + version);
        } else {
            Log.e(TAG, "FooManager service not found!");
        }
    }
}
```

## Checkpoint

<Checkpoint
  quiz={{
    question: 'Why MUST a SystemService execute Binder.clearCallingIdentity() before calling a downstream HAL or database?',
    options: [
      'To make the call execute asynchronously in another thread.',
      'Because the downstream HAL requires the privileges of system_server (UID 1000) rather than the calling app’s untrusted sandbox UID.',
      'To prevent Java garbage collection from deleting the Binder stub.',
      'Because clearCallingIdentity() compresses the parcel payload.',
    ],
    answer: 1,
    explain:
      'When an app invokes an IPC method, the thread retains the app’s UID. If system_server attempts to call a vendor HAL or read a secure database without clearing identity, the downstream service will reject the call because the app lacks hardware or root permissions.',
  }}
/>

<BreakIt
  items={[

## Troubleshooting

<Troubleshooting
  items={[
    {
      symptom: 'system_server crashes during boot with NullPointerException',
      cause: 'SystemService constructor attempted to talk to dependent services before onBootPhase/onStart.',
      fix: 'Defer cross-service IPC until PHASE_BOOT_COMPLETED or PHASE_SYSTEM_SERVICES_READY lifecycle callbacks.',
    },
    {
      symptom: 'App gets SecurityException: Requires custom permission',
      cause: 'Calling app does not declare the required <uses-permission> in AndroidManifest.xml.',
      fix: 'Add the permission to the client app manifest and grant it via adb shell pm grant if signature/runtime.',
    },
    {
      symptom: 'ServiceManager.getService("myservice") returns null in app',
      cause: 'Service published with ServiceManager.addService without Context.SYSTEM_SERVICE_PUBLISHED visibility.',
      fix: 'Register the service through publishBinderService() inside your SystemService subclass.',
    },
  ]}
