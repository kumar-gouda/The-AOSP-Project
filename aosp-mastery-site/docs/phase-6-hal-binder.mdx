## 2. Project Treble: Why HALs Look The Way They Do

Before Android 8.0, Android was monolithic: platform framework code directly linked against vendor `.so` libraries. When Android released a new OS version, device manufacturers had to wait months for chip vendors to rebuild their custom shared libraries.

Treble split the system clean in half along the **Treble Seam**:

```
+-------------------------------------------------------------+
|                      /system Partition                      |
|  Java Framework (system_server) & Platform Native Daemons   |
+-------------------------------------------------------------+
                              |
                     Treble AIDL Interface
             (Stable IPC Contract via /dev/binder)
                              |
+-------------------------------------------------------------+
|                      /vendor Partition                      |
|         HAL Daemons (e.g., vendor.foo-service)              |
|                              |                              |
|                   ioctl / sysfs / /dev/foo                  |
|                              v                              |
|                 Linux Kernel Device Drivers                 |
+-------------------------------------------------------------+
```

## 3. AIDL Architecture: The Proxy-Stub Pattern

When two processes communicate across Binder, they cannot share memory pointers. Instead, the AIDL compiler (`aidl-cpp` or `aidl`) generates the **Proxy-Stub** pattern:

```
+---------------------+                      +---------------------+
|   Client Process    |                      |   Server Process    |
|                     |                      | (vendor.foo-service)|
|   +---------------+ |                      |  +---------------+  |
|   |  IFoo Client  | |                      |  |   FooImpl     |  |
|   +-------+-------+ |                      |  +-------^-------+  |
|           |         |                      |          |          |
|   +-------v-------+ |                      |  +-------+-------+  |
|   |  BpFoo Proxy  | |                      |  |   BnFoo Stub  |  |
|   |  (Marshaling) | |                      |  |(Demarshaling) |  |
|   +-------+-------+ |                      |  +-------^-------+  |
+-----------|---------+                      +----------|----------+
            | ioctl(BINDER_WRITE_READ)                  |
            |                                           |
            v                                           |
    +---------------------------------------------------+---+
    |                 Linux Kernel Driver                   |
    |  /dev/binder: Single-copy mmap transfer to Server     |
    +-------------------------------------------------------+
```

<DeepDive title="Under the Hood: BpInterface vs BnInterface in C++">
In AOSP's C++ Binder implementation:
- **`BpFoo` (Binder Proxy):** "Bp" stands for **Binder Proxy**. It lives in the client's address space. When you call `proxy->hello()`, `BpFoo` writes the transaction code (`TRANSACTION_hello`) and serializes the arguments into a `Parcel` object. It then calls `remote()->transact()`, which triggers `ioctl(BINDER_WRITE_READ)`.
- **`BnFoo` (Binder Native):** "Bn" stands for **Binder Native** (often called the **Stub**). It lives in the server's address space. It inherits from `BBinder`. When the server's Binder thread pool wakes up with incoming data, it calls `BnFoo::onTransact()`. `BnFoo` reads the transaction code from the `Parcel`, deserializes the arguments, and calls your concrete C++ implementation method `hello()`. The return value is written into a reply `Parcel` and sent back through the kernel.
- **`libbinder_ndk` (`ndk::SharedRefBase`):** In modern AIDL HALs, instead of the legacy `sp<IFoo>` / `libbinder` framework, we use `libbinder_ndk`. The generated classes are `aid::android::hardware::foo::BnFoo` and use standard `std::shared_ptr` instead of platform-internal `sp<>`. This ensures binary stability across OS versions.
</DeepDive>

## 4. Defining the AIDL Interface

Create the interface file under `hardware/interfaces/foo/aidl/android/hardware/foo/IFoo.aidl`:

```aidl
// hardware/interfaces/foo/aidl/android/hardware/foo/IFoo.aidl
package android.hardware.foo;

/**
 * IFoo Hardware Abstraction Layer interface.
 * Exposes hardware telemetry and test methods across the Treble boundary.
 */
@VintfStability
interface IFoo {
    /**
     * Returns the hardware driver version.
     */
    int getVersion();

    /**
     * Sends a ping to hardware registers and returns status message.
     */
    String hello();
}
```

Now declare the `aidl_interface` module in `hardware/interfaces/foo/aidl/Android.bp`:

## 5. Implementing the HAL Service in C++

Now write the concrete HAL service in `hardware/interfaces/foo/aidl/default/`.

### Header: `Foo.h`

```cpp
// Foo.h
#pragma once

#include <aidl/android/hardware/foo/BnFoo.h>

namespace aidl::android::hardware::foo {

class Foo : public BnFoo {
public:
    ndk::ScopedAStatus getVersion(int32_t* _aidl_return) override;
    ndk::ScopedAStatus hello(std::string* _aidl_return) override;
};

}  // namespace aidl::android::hardware::foo
```

### Implementation: `Foo.cpp`

```cpp
// Foo.cpp
#include "Foo.h"
#include <android-base/logging.h>

namespace aidl::android::hardware::foo {

ndk::ScopedAStatus Foo::getVersion(int32_t* _aidl_return) {
    LOG(INFO) << "Foo HAL: getVersion() called";
    *_aidl_return = 1;
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Foo::hello(std::string* _aidl_return) {
    LOG(INFO) << "Foo HAL: hello() called";
    *_aidl_return = "hello from IFoo AIDL HAL";
    return ndk::ScopedAStatus::ok();
}

}  // namespace aidl::android::hardware::foo
```

### Main Entry Point: `service.cpp`

The service process registers with `servicemanager` and enters the Binder worker thread pool:

```cpp
// service.cpp
#include "Foo.h"

#include <android-base/logging.h>
#include <android/binder_manager.h>
#include <android/binder_process.h>

using aidl::android::hardware::foo::Foo;

int main() {
    // 1. Initialize structured logging
    android::base::InitLogging(nullptr, android::base::LogdLogger(android::base::SYSTEM));
    LOG(INFO) << "Starting Foo AIDL HAL Service...";

    // 2. Configure Binder thread pool (0 extra threads = main thread handles transactions)
    ABinderProcess_setThreadPoolMaxThreadCount(0);

    // 3. Instantiate the HAL implementation via NDK shared pointer
    std::shared_ptr<Foo> foo = ndk::SharedRefBase::make<Foo>();

    // 4. Construct the canonical service instance name: <package>.<interface>/<instance>
    const std::string instance = std::string(Foo::descriptor) + "/default";

    // 5. Register with servicemanager
    binder_status_t status = AServiceManager_addService(foo->asBinder().get(), instance.c_str());
    CHECK_EQ(status, STATUS_OK) << "Failed to register Foo AIDL HAL service: " << status;

    LOG(INFO) << "Foo AIDL HAL registered successfully as: " << instance;

    // 6. Join the thread pool to process incoming IPC requests
    ABinderProcess_joinThreadPool();

    return EXIT_FAILURE;  // Should never reach here
}
```

### `init.rc` Configuration

Tell `init` how to launch your HAL at boot time (`hardware/interfaces/foo/aidl/default/vendor.foo-service.rc`):

```text
service vendor.foo-service /vendor/bin/hw/vendor.foo-service
    class hal
    user nobody
    group nobody
    shutdown critical
```

## 6. VINTF: The Compatibility Manifest

Before Android will allow a client to discover an AIDL HAL, the HAL must be declared in the **VINTF (Vendor Interface)** manifest. If the manifest is missing or mismatched, `AServiceManager_waitForService()` will fail and the system will log a security policy rejection.

Add this stanza to your device's `/vendor/etc/vintf/manifest.xml`:

```xml
<manifest version="1.0" type="device">
    <hal format="aidl">
        <name>android.hardware.foo</name>
        <version>1</version>
        <interface>
            <name>IFoo</name>
            <instance>default</instance>
        </interface>
        <fqname>IFoo/default</fqname>
    </hal>
</manifest>
```

<WhyItWorked>
During the boot sequence, `init` and the framework read `/system/etc/vintf/compatibility_matrix.xml` and `/vendor/etc/vintf/manifest.xml`. The VINTF parser matches every `<hal>` required by the framework against the `<hal>` instances provided by the vendor. If an interface version does not match, the device halts with a fatal compatibility error before corrupted data can reach userspace.
</WhyItWorked>

## 7. Native Client & End-to-End Testing

To prove your HAL functions end-to-end, write a small native command-line client (`foo_client.cpp`):

```cpp
// foo_client.cpp
#include <aidl/android/hardware/foo/IFoo.h>
#include <android/binder_manager.h>
#include <iostream>

using aidl::android::hardware::foo::IFoo;

int main() {
    const std::string instance = std::string(IFoo::descriptor) + "/default";
    
    // Connect to the service via servicemanager
    AIBinder* binder = AServiceManager_waitForService(instance.c_str());
    if (!binder) {
        std::cerr << "Failed to find HAL service: " << instance << std::endl;
        return 1;
    }

    // Wrap the raw AIBinder in the generated typed IFoo proxy
    std::shared_ptr<IFoo> client = IFoo::fromBinder(ndk::SpAIBinder(binder));
    if (!client) {
        std::cerr << "Failed to create IFoo proxy wrapper" << std::endl;
        return 1;
    }

    int32_t version = 0;
    ndk::ScopedAStatus status = client->getVersion(&version);
    if (!status.isOk()) {
        std::cerr << "RPC failed: " << status.getDescription() << std::endl;
        return 1;
    }

    std::string msg;
    client->hello(&msg);

    std::cout << "HAL Response: " << msg << " (v" << version << ")" << std::endl;
    return 0;
}
```

Every registered Binder service allocates a 1 MB shared buffer space (via `mmap`) inside `/dev/binder`. The debugfs entry exposes the active Binder nodes (`node 58`), the thread pool state, and the remaining free buffer size.
</WhyItWorked>

## 9. Writing a VTS Test for Your HAL

In AOSP, vendor compliance is verified using the **Vendor Test Suite (VTS)**. VTS tests run as Google Test (GTest) binaries that execute across the Binder interface on live hardware:

```cpp
// VtsHalFooTargetTest.cpp
#include <aidl/Gtest.h>
#include <aidl/Vintf.h>
#include <aidl/android/hardware/foo/IFoo.h>
#include <android/binder_manager.h>
#include <gtest/gtest.h>

using aidl::android::hardware::foo::IFoo;

class FooAidlTest : public testing::TestWithParam<std::string> {
public:
    void SetUp() override {
        foo = IFoo::fromBinder(ndk::SpAIBinder(
            AServiceManager_waitForService(GetParam().c_str())));
        ASSERT_NE(foo, nullptr);
    }

    std::shared_ptr<IFoo> foo;
};

TEST_P(FooAidlTest, VerifyVersionIsPositive) {
    int32_t version = 0;
    auto status = foo->getVersion(&version);
    EXPECT_TRUE(status.isOk());
    EXPECT_GE(version, 1);
}

TEST_P(FooAidlTest, VerifyHelloReturnsNonEmptyString) {
    std::string msg;
    auto status = foo->hello(&msg);
    EXPECT_TRUE(status.isOk());
    EXPECT_FALSE(msg.empty());
}

// Automatically instantiate test for all instances declared in VINTF
INSTANTIATE_TEST_SUITE_P(
    PerInstance, FooAidlTest,
    testing::ValuesIn(android::getAidlHalInstanceNames(IFoo::descriptor)),
    android::PrintInstanceNameToString);
```
