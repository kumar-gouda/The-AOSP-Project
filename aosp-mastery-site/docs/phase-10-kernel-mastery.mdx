## 3. Writing a Kernel Module with a `/proc` Entry

Let's write `hello_kmod.c`. This module demonstrates safe string formatting using the kernel `seq_file` interface:

<CodeAnnotator
  title="hello_kmod.c: Safe Loadable Kernel Module with procfs Node"
  code={`#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/proc_fs.h>
#include <linux/seq_file.h>

#define PROC_NAME "hello_kmod"

static int hello_show(struct seq_file *m, void *v) {
    seq_printf(m, "hello_kmod: status=active version=1 kmi_compatible=true\\n");
    return 0;
}

static int hello_open(struct inode *inode, struct file *file) {
    return single_open(file, hello_show, NULL);
}

static const struct proc_ops hello_proc_ops = {
    .proc_open    = hello_open,
    .proc_read    = seq_read,
    .proc_lseek   = seq_lseek,
    .proc_release = single_release,
};

static int __init hello_init(void) {
    struct proc_dir_entry *entry;
    entry = proc_create(PROC_NAME, 0444, NULL, &hello_proc_ops);
    if (!entry) {
        pr_err("hello_kmod: failed to create /proc/%s\\n", PROC_NAME);
        return -ENOMEM;
    }
    pr_info("hello_kmod: module loaded successfully\\n");
    return 0;
}

static void __exit hello_exit(void) {
    remove_proc_entry(PROC_NAME, NULL);
    pr_info("hello_kmod: module unloaded\\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("AOSP Mastery Engineer");
MODULE_DESCRIPTION("Minimal ACK /proc diagnostic kernel module");
MODULE_VERSION("1.0");`}
  annotations={[

## 4. Building with Kleaf Bazel

In modern Android kernels (ACK 5.10+ / 6.1+), modules are compiled using Kleaf. Add this rule to your driver directory `BUILD.bazel`:

```python
# BUILD.bazel
load("//build/kernel/kleaf:kernel.bzl", "kernel_module")

kernel_module(
    name = "hello_kmod",
    srcs = ["hello_kmod.c"],
    outs = ["hello_kmod.ko"],
    kernel_build = "//common:kernel_aarch64",
)
```

Compile with Bazel:

```bash
tools/bazel build //common-modules/virtual-device:hello_kmod
```

## 5. Loading and Verifying on Cuttlefish

Push the compiled `.ko` to the device and inspect both userspace and kernel space:

<TestRunner
  title="Load Kernel Module & Inspect Telemetry"
  cmd={`adb root
adb push bazel-bin/common-modules/virtual-device/hello_kmod.ko /data/local/tmp/
adb shell insmod /data/local/tmp/hello_kmod.ko
adb shell cat /proc/hello_kmod
adb shell dmesg | grep hello_kmod | tail -n 5`}
  expect={`hello_kmod: status=active version=1 kmi_compatible=true
[  142.128450] hello_kmod: module loaded successfully`}
/>

<WhyItWorked>
When you executed `insmod`, the kernel verified the ELF file header, checked that exported symbols matched the KMI whitelist, allocated executable kernel pages, executed `hello_init()`, and registered `/proc/hello_kmod`. When `cat` read the file, the VFS invoked `hello_show()`, streaming the string to userspace.
</WhyItWorked>

## 6. Dissecting a Kernel Crash: The Oops

What happens if a kernel module contains a bug, such as dereferencing a NULL pointer?

```c
// Deliberate null pointer dereference bug:
int *bad_ptr = NULL;
*bad_ptr = 42;
```

When this executes, the CPU generates a hardware Page Fault. Because the fault occurs in EL1 (Kernel Mode), the kernel generates an **Oops**:

<DeepDive title="Decoding a 64-bit ARM Kernel Oops Log">
```text
[  184.210405] Unable to handle kernel NULL pointer dereference at virtual address 0000000000000000
[  184.210410] Mem abort info:
[  184.210412]   ESR = 0x96000046
[  184.210414]   EC = 0x25: DABT (current EL), IL = 32 bits
[  184.210416]   SET = 0, FnV = 0
[  184.210418]   EA = 0, S1PTW = 0
[  184.210420]   FSC = 0x06: level 2 translation fault
[  184.210422] Data abort info:
[  184.210424]   ISV = 0, ISS = 0x00000046
[  184.210426]   CM = 0, WnR = 1
[  184.210428] user pgtable: 4k pages, 39-bit VAs, pgdp=0000000084512000
[  184.210430] [0000000000000000] pgd=0000000000000000, p4d=0000000000000000
[  184.210435] Internal error: Oops: 96000046 [#1] PREEMPT SMP
[  184.210440] CPU: 1 PID: 1845 Comm: cat Tainted: G           O      6.1.25-android14-gki #1
[  184.210445] pc : hello_show+0x18/0x34 [hello_kmod]
[  184.210450] lr : seq_read_iter+0x17c/0x4a0
[  184.210455] Call trace:
[  184.210460]  hello_show+0x18/0x34 [hello_kmod]
[  184.210465]  seq_read_iter+0x17c/0x4a0
[  184.210470]  proc_reg_read_iter+0x80/0xb8
[  184.210475]  vfs_read+0x1e8/0x2c0
[  184.210480]  ksys_read+0x68/0xf4
```

**Key Information to Extract:**
- **ESR (`0x96000046`):** Exception Syndrome Register. `EC = 0x25` indicates a Data Abort from the current Exception Level (EL1).
- **`WnR = 1`:** Write-not-Read. The CPU attempted to *write* to the faulting address.
- **`pc : hello_show+0x18`:** The crash occurred exactly 24 bytes (0x18) into the `hello_show` function inside `hello_kmod.ko`.
- **`Call trace:`** Shows the exact sequence of kernel VFS calls leading up to the crash.
</DeepDive>

## 7. Testing Kernel Code with KUnit

Rather than manually crashing or logging, professional kernel engineers write in-kernel unit tests using **KUnit**:

```c
// hello_test.c - In-kernel KUnit test
#include <kunit/test.h>

static void test_hello_version(struct kunit *test) {
    int version = 1;
    KUNIT_EXPECT_EQ(test, version, 1);
}

static struct kunit_case hello_test_cases[] = {
    KUNIT_CASE(test_hello_version),
    {}
};

static struct kunit_suite hello_test_suite = {
    .name = "hello_kmod_tests",
    .test_cases = hello_test_cases,
};

kunit_test_suite(hello_test_suite);
```

Run via Kleaf Bazel:

```bash
tools/bazel test //common-modules/virtual-device:hello_kmod_tests
```
