### Symbolicating with `ndk-stack`

On the device, binaries are stripped of DWARF symbols to save flash space. On your build machine, the unstripped binaries live in `out/target/product/<target>/symbols/`:

<TestRunner
  title="Symbolicate the Crash Backtrace"
  cmd={`adb logcat -d -b crash | ndk-stack -sym $ANDROID_PRODUCT_OUT/symbols`}
  expect={`********** Crash dump: **********
Build fingerprint: 'Android/cf_x86_64_phone/...'
pid: 1420, tid: 1420, name: vendor.foo-serv  >>> /vendor/bin/hw/vendor.foo-service <<<
signal 11 (SIGSEGV), code 1 (SEGV_MAPERR), fault addr 0x0
Stack frame #00 pc 0000000000042a10 /vendor/bin/hw/vendor.foo-service: 
  aidl::android::hardware::foo::Foo::getVersion(int*) at hardware/interfaces/foo/aidl/default/Foo.cpp:18:9
Stack frame #01 pc 000000000003fa8c /vendor/bin/hw/vendor.foo-service: 
  main at hardware/interfaces/foo/aidl/default/service.cpp:32:15`}
/>

<WhyItWorked>
`ndk-stack` reads the `.debug_info` and `.debug_line` sections of the unstripped ELF binary on your host workstation. It resolves `pc 00042a10` directly to `Foo.cpp:18:9`. In one command, a cryptic hexadecimal crash dump becomes an exact source code line.
</WhyItWorked>

## 4. Performance Profiling: Perfetto

When a device is not crashing, but dropping frames (jank) or lagging during app launch, **Perfetto** captures the full system execution timeline:

<TestRunner
  title="Record a 10-Second Perfetto System Trace"
  cmd={`adb shell perfetto \\
  -c - --txt \\
  -o /data/misc/perfetto-traces/trace.pftrace <<'EOF'
buffers: {
    size_kb: 65536
    fill_policy: RING_BUFFER
}
data_sources: {
    config {
        name: "linux.ftrace"
        ftrace_config {
            ftrace_events: "sched/sched_switch"
            ftrace_events: "power/cpu_frequency"
            ftrace_events: "binder/*"
            atrace_categories: "am"
            atrace_categories: "wm"
            atrace_categories: "view"
        }
    }
}
duration_ms: 10000
EOF

adb pull /data/misc/perfetto-traces/trace.pftrace ./`}
  expect={`[ perfetto ] Connected to tracing daemon
[ perfetto ] Tracing started
[ perfetto ] Tracing stopped, 45281 KB written to /data/misc/perfetto-traces/trace.pftrace
trace.pftrace: 1 file pulled`}
/>

<DeepDive title="Querying Perfetto Traces with SQL">
You don't just look at traces visually at `ui.perfetto.dev` — Perfetto traces can be queried programmatically with SQL! 

For example, to find the slowest Binder calls in your trace:
```sql
SELECT
  ts,
  dur / 1e6 AS dur_ms,
  slice.name,
  process.name AS process_name
FROM slice
JOIN thread_track ON slice.track_id = thread_track.id
JOIN thread USING (utid)
JOIN process USING (upid)
WHERE slice.name LIKE 'binder transaction%'
ORDER BY dur DESC
LIMIT 5;
```
This query reveals the exact thread, timestamp, and duration of long IPC bottlenecks that cause UI stutter.
</DeepDive>

## 5. Kernel-Side Tracing: `ftrace`

When debugging kernel drivers or device node contention directly from a shell:

```bash
# 1. Select the function graph tracer
adb shell "echo function_graph > /sys/kernel/tracing/current_tracer"

# 2. Filter to your driver functions to avoid buffer flooding
adb shell "echo 'foo_*' > /sys/kernel/tracing/set_ftrace_filter"

# 3. Start tracing
adb shell "echo 1 > /sys/kernel/tracing/tracing_on"

# 4. Trigger the driver action via client CLI
adb shell /vendor/bin/foo_client

# 5. Stop tracing and read output
adb shell "echo 0 > /sys/kernel/tracing/tracing_on"
adb shell cat /sys/kernel/tracing/trace | head -n 30
```

## 6. Hands-On Lab: The Three Seeded Bugs

To achieve mastery, you must diagnose **three distinct bugs** introduced into your Project Spine using **only on-device evidence**:

### Bug 1: The Null Pointer Crash (Native Userspace)
- **Symptom:** The HAL daemon crashes as soon as `getVersion()` is called.
- **Evidence:** Capture tombstone `/data/tombstones/tombstone_00`. Identify `SIGSEGV (SEGV_MAPERR)` with `fault addr 0x0`. Symbolicate with `ndk-stack` to locate the missing null check in `Foo.cpp`.
- **Root Cause & Fix:** Add null pointer validation before accessing member fields.

### Bug 2: The Binder Priority Inversion (Framework & UI)
- **Symptom:** App UI hitches for 150ms when pressing a button that talks to `FooService`.
- **Evidence:** Record a Perfetto trace. Inspect the main thread track and observe it in `Sleeping` state inside `ioctl(BINDER_WRITE_READ)`. Trace the server thread in `system_server` and see it blocked waiting on a `synchronized(mLock)` held by a background sync task.
- **Root Cause & Fix:** Move heavy lock-guarded disk I/O out of the synchronous AIDL method into an asynchronous `HandlerThread`.

### Bug 3: The Driver Deadlock / Spinlock Hang (Kernel)
- **Symptom:** Calling the HAL causes the calling process to hang in `D` (Uninterruptible Sleep) state.
- **Evidence:** Run `adb shell ps -A -o PID,NAME,STATE,WCHAN | grep foo`. Observe `D` state with `wchan` pointing to `mutex_lock_killable`. Inspect `dmesg` to find kernel lockdep warning `possible recursive locking detected`.
- **Root Cause & Fix:** Release the mutex before calling a re-entrant function inside the kernel driver.
