## Why this phase exists

AOSP userspace is C++17/C++20. The kernel is C in a distinct dialect: no STL,
manual memory, kernel idioms. These are two separate skills, and the plan
assumes you have neither yet. Learning them here - before Phase 0's environment
gate - means every later phase is about Android, not about fighting the
language.

## Track A - C++17 for AOSP userspace (~3-4 weeks)

The goal is a tested, memory-safe library. You will meet the exact features AOSP
relies on.

### A1. RAII and smart pointers

Do this: write a small type that owns a resource, then make ownership explicit
with `std::unique_ptr`.

```cpp
// owner.h
#pragma once
#include <memory>
#include <string>

struct Buffer {
  explicit Buffer(std::size_t n) : data_(std::make_unique<char[]>(n)), size_(n) {}
  char*       data()       { return data_.get(); }
  std::size_t size() const { return size_; }
 private:
  std::unique_ptr<char[]> data_;
  std::size_t             size_;
};
```

<WhyItWorked>
`std::unique_ptr` expresses single ownership: the `Buffer` frees its storage when
it goes out of scope, with no manual `delete`. This is the same RAII pattern at
the heart of AOSP's `sp<>`/`wp<>` in the native userspace, and it is why system
C++ largely avoids exceptions and manual `new`/`delete`.
</WhyItWorked>

### A2. Move semantics and const-correctness

Do this: make your type movable and pass it by `const&` where you only read.

```cpp
#include <type_traits>
static_assert(std::is_move_constructible_v<Buffer>);
```

### A3. optional, variant, string_view

Do this: model "value or nothing" without a sentinel, and read strings without
copying.

```cpp
#include <cstdlib>      // for std::atoi
#include <optional>
#include <string>       // for std::string
#include <string_view>

std::optional<int> parse(const std::string_view s) {
  if (s.empty()) return std::nullopt;
  return std::atoi(std::string(s).c_str());
}
```

### A4. Error-as-return-value (AOSP avoids exceptions in system code)

Do this: return an error alongside the value instead of throwing.

```cpp
struct Result {
  bool ok;
  int  value;
};
```

### A5. Google C++ style, clang-format, clang-tidy, and GTest

Do this: format and lint your library, then write your first unit test.

```bash
clang-format -i owner.h
```

Write a first GTest (`owner_test.cpp`):

```cpp
#include <gtest/gtest.h>
#include "owner.h"

TEST(BufferTest, Allocates) {
  Buffer b(16);
  EXPECT_EQ(b.size(), 16u);
  EXPECT_NE(b.data(), nullptr);
}
```

## Track B - systems-C for kernel work (~2-3 weeks)

The goal is fluency with the C dialect the kernel actually uses.

### B1. Pointers, pointer arithmetic, and container_of

Do this: walk an array with a pointer, then recover a struct from a member
pointer the way the kernel's `container_of` does.

```c
/* b1_container_of.c */
#include <stddef.h>
#include <stdio.h>

#define container_of(ptr, type, member) \
  ((type *)((char *)(ptr) - offsetof(type, member)))

struct item { int value; char name[8]; };

int main(void) {
  struct item it = { .value = 42, .name = "aosp" };
  int *vp = &it.value;
  struct item *back = container_of(vp, struct item, value);
  printf("value=%d name=%s\n", back->value, back->name);
  return 0;
}
```

```bash
gcc -std=c11 -Wall -Wextra b1_container_of.c -o b1 && ./b1
```

Expected (author-run pending):

```text
value=42 name=aosp
```

### B2. volatile, alignment, and endianness

Do this: observe byte order with real addresses.

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
  uint32_t x = 0x01020304;
  unsigned char *p = (unsigned char *)&x;
  printf("first byte: 0x%02x\n", p[0]);   /* 0x04 => little-endian */
  return 0;
}
```

### B3. ERR_PTR / IS_ERR

Do this: encode an error in a pointer, the kernel's way of returning both.

```c
#define MAX_ERRNO 4095
#define IS_ERR_VALUE(x) ((unsigned long)(void *)(x) >= (unsigned long)-MAX_ERRNO)
static inline int IS_ERR(const void *ptr) { return IS_ERR_VALUE((unsigned long)ptr); }
```

### B4. The compilation model: ELF, ABI, readelf/objdump/nm

Do this: compile a tiny program and inspect its ABI directly.

```c
/* b4_abi.c */
#include <stdio.h>

struct s { char c; int i; long l; };

int main(void) {
  printf("sizeof(struct s) = %zu\n", sizeof(struct s));
  return 0;
}
```

```bash
gcc -std=c11 -O0 b4_abi.c -o b4
./b4
objdump -d b4 | sed -n '1,12p'
```

Expected (author-run pending; exact offsets are ABI-dependent - x86-64 shown):

```text
sizeof(struct s) = 16
```

### B5. Cross-compilation to aarch64

Do this: build the same program for AOSP's primary architecture.

```bash
sudo apt-get install -y gcc-aarch64-linux-gnu
aarch64-linux-gnu-gcc -std=c11 b4_abi.c -o b4_arm64
file b4_arm64
```

Expected (author-run pending):

```text

```

<BreakIt
  items={[
    'Symptoms: g++ errors "operator= is implicitly deleted" after adding a unique_ptr member. Cause: unique_ptr is move-only, so the class copy is deleted. Fix: pass by value and std::move, or declare move operations explicitly.',

<Checkpoint
