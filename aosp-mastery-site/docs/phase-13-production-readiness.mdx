<DidYouKnow title="Why Google Rewrote Android Keystore & Bluetooth in Rust">
  According to official Android security telemetry between 2014 and 2020, over <strong>70% of all severe security vulnerabilities</strong> in Android were memory safety flaws in C and C++ (buffer overflows, use-after-free, and race conditions).
  <br /><br />
  <strong>The Strategic Pivot:</strong> Starting in Android 12, Google introduced first-class support for <strong>Rust</strong> in AOSP. Rather than attempting to patch millions of lines of legacy C++, Google prioritized rewriting the most high-risk, attack-facing components in Rust:
  <ul>
    <li><code>Keystore2</code> (<code>/system/bin/keystore2</code>): Android's master cryptographic key management daemon.</li>
    <li><code>Fluoride / Gabeldorsche</code>: Android's core Bluetooth stack that parses untrusted over-the-air radio packets.</li>
    <li><code>crosvm / Microdroid</code>: The Android Virtualization Framework hypervisor.</li>
  </ul>
  <strong>The Result:</strong> In the rewritten components, memory corruption vulnerabilities dropped to <strong>zero</strong>. Because Rust compiles to bare-metal machine code without a garbage collector or Java VM overhead, memory consumption and latency were equal to or better than C++!
</DidYouKnow>

## 3. Writing a Production Rust Component in AOSP

Let's author a memory-safe hardware monitoring daemon in Rust (`spine_daemon/src/main.rs`):

```rust
// spine_daemon/src/main.rs
use log::{info, LevelFilter};
use android_logger::Config;

fn calculate_health_metric(temperature_celsius: i32, voltage_mv: i32) -> Result<u32, &'static str> {
    if temperature_celsius > 90 {
        return Err("Thermal critical: overheating detected");
    }
    if voltage_mv < 3000 {
        return Err("Undervoltage detected");
    }
    // Safe arithmetic - Rust guarantees no integer overflow wraps silently
    Ok((voltage_mv as u32) / (temperature_celsius as u32 + 273))
}

fn main() {
    android_logger::init_once(
        Config::default()
            .with_tag("SpineRustDaemon")
            .with_max_level(LevelFilter::Info),
    );

    info!("Spine Rust daemon initialized under AOSP native runtime");

    match calculate_health_metric(42, 3800) {
        Ok(metric) => info!("Hardware telemetry metric: {}", metric),
        Err(e) => log::error!("Telemetry check failed: {}", e),
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_thermal_cutoff() {
        assert!(calculate_health_metric(95, 3800).is_err());
    }

    #[test]
    fn test_nominal_reading() {
        assert!(calculate_health_metric(40, 3800).is_ok());
    }
}
```

## 4. Packaging the Component into an APEX

Package your native Rust daemon into an updatable APEX container:

### `Android.bp` APEX Rule

```text
apex {
    name: "com.android.spine",
    manifest: "apex_manifest.json",
    binaries: ["spine_rust_daemon"],
    key: "com.android.spine.key",
    certificate: ":com.android.spine.certificate",
    updatable: true,
}

apex_key {
    name: "com.android.spine.key",
    public_key: "com.android.spine.avbpubkey",
    private_key: "com.android.spine.pem",
}

android_app_certificate {
    name: "com.android.spine.certificate",
    certificate: "com.android.spine",
}
```

### `apex_manifest.json`

```json
{
  "name": "com.android.spine",
  "version": 1
}
```

<WhyItWorked>
During the build, Soong creates an ext4 disk image containing `/bin/spine_rust_daemon`, generates `apex_manifest.json`, and signs the payload with your private key. When flashed, `apexd` mounts the image at `/apex/com.android.spine/`, making the binary available at `/apex/com.android.spine/bin/spine_rust_daemon`.
</WhyItWorked>

## 5. The Hardware-to-Screen Seam: Graphics & Camera

Commercial Android platforms rely heavily on zero-copy hardware graphics pipelines. Understand where the OS ends and silicon begins:

```
+---------------------------------------------------------------+
|                       App UI (RenderThread)                   |
|  Draws UI into GraphicBuffer via Vulkan or Skia OpenGL ES     |
+-------------------------------+-------------------------------+
                                |
                                v
+---------------------------------------------------------------+
|                     Gralloc HAL (vendor)                      |
|  Allocates contiguous physical RAM backed by dma-buf          |
+-------------------------------+-------------------------------+
                                |
                                v
+---------------------------------------------------------------+
|                    SurfaceFlinger (system)                    |
|  Receives layers from all visible windows; computes Z-order   |
+-------------------------------+-------------------------------+
                                |
                                v
+---------------------------------------------------------------+
|                    Hardware Composer (HWC)                    |
|  Offloads layers directly to display controller hardware      |
+---------------------------------------------------------------+
```

<DeepDive title="Why Gralloc and DMA-BUF are Fundamental to Android Performance">
If an Android camera stream had to copy 4K video frames from camera memory to CPU RAM, and then copy them again to GPU memory for display rendering, the phone would overheat and drop frames. 

Instead, **Gralloc** allocates a Linux **`dma-buf`** (Direct Memory Access Buffer). The camera hardware writes pixel data directly into the buffer; the GPU reads the buffer directly as a texture; and the display processor reads it directly to refresh the screen. **Zero memory copies occur across the entire pipeline!**
</DeepDive>

## 6. Host-Orchestrated Testing: Trade Federation

To test your full stack across reboots and complex states, author a host-driven test module in `SpineHostTest.java`:

```java
// SpineHostTest.java
package com.android.tests.spine;

import com.android.tradefed.device.DeviceNotAvailableException;
import com.android.tradefed.device.ITestDevice;
import com.android.tradefed.testtype.DeviceTestCase;

public class SpineHostTest extends DeviceTestCase {
    private ITestDevice mDevice;

    @Override
    protected void setUp() throws Exception {
        super.setUp();
        mDevice = getDevice();
        assertNotNull("No test device available", mDevice);
    }

    public void testDaemonRunsAfterReboot() throws DeviceNotAvailableException {
        // Verify daemon is running
        String pids = mDevice.executeShellCommand("pidof spine_rust_daemon").trim();
        assertFalse("Daemon not running prior to reboot", pids.isEmpty());

        // Reboot the physical hardware
        mDevice.reboot();

        // Verify daemon restored by init
        String pidsAfter = mDevice.executeShellCommand("pidof spine_rust_daemon").trim();
        assertFalse("Daemon failed to restart after system reboot", pidsAfter.isEmpty());
    }
}
```

## 7. The Production Architecture Matrix

Before shipping any major platform capability, a lead AOSP architect must map its impact across every single OS layer:

| Subsystem Layer | Commercial Ship Requirements |
|-----------------|------------------------------|
| **Linux Kernel** | Loadable module in `vendor_boot`, Device Tree node in `dtbo.img`, KUnit passing. |
| **Hardware Seam** | Stable AIDL HAL annotated `@VintfStability`, VINTF `manifest.xml`, VTS passing. |
| **Platform Framework** | `SystemService` registered in `SystemServer`, app-facing Manager API, unit tests. |
| **Security & Privacy** | Isolated SELinux `.te` domain, zero AVC denials, compile-time `neverallow` compliant. |
| **Packaging & Modularity** | Delivered as an updatable APEX container or GKI KMI-compatible `.ko`. |
| **Quality & Fleet Verification** | Enrolled in CTS (`CtsSecurityHostTestCases`) and Tradefed test suites. |
| **Physical Storage** | Resides in proper dynamic sub-partition (`system`, `vendor`, or `product`). |

  title="Phase 13 Production Hardening Traps & Gotchas"
  traps={[
    {
      name: 'The Early Init vs. APEX Mount Race Condition',
      symptom: 'A daemon started in "on early-init" or "on init" crashes immediately with "dlopen failed: library \\"libc.so\\" not found".',
      cause: 'APEX containers (including the Bionic runtime APEX com.android.runtime) are not mounted until the "post-fs-data" boot stage. Early daemons cannot load libraries from /apex/.',
      fix: 'Early native daemons must link against bootstrap libraries installed directly in /system/bin/bionic/ or mark recovery_available: true.',
    },
    {
      name: 'The Third-Party Rust Crate Visibility Trap',
      symptom: 'Cargo.toml dependency compiles on host Linux, but Soong fails with: "error: cannot find crate \'my_crate\'".',
      cause: 'AOSP builds are hermetic and cannot access crates.io over the network. Every Rust dependency must be checked into external/rust/crates/ with an autogenerated Android.bp.',
      fix: 'Use the AOSP cargo2android or cargo_embargo tool to generate compliant Android.bp module files for required crates in the external/ directory.',
    },
    {
      name: 'The Gralloc dma-buf File Descriptor Leak',
      symptom: 'Camera preview or video playback works for 10 minutes, then stutters and crashes with "out of graphic memory" or kernel CMA exhaustion.',

      fix: 'Always pair native_handle_clone() with native_handle_close() and native_handle_delete(), or wrap handles in std::unique_ptr with custom deleters.',
