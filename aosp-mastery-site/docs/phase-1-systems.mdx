## 1. Userspace vs. Kernel: The Virtual Memory Model

Every process runs in its own private world. If Process A has an integer at address `0x7ffee420`, and Process B has an integer at address `0x7ffee420`, **they point to completely different physical silicon chips in your RAM**!

```text
Process A Virtual Address Space           Physical RAM Frames            Process B Virtual Address Space
┌───────────────────────────────┐        ┌─────────────────────┐        ┌───────────────────────────────┐
│ Stack (local variables)       │───────>│ Frame 104 (Page A)  │        │ Stack (local variables)       │
├───────────────────────────────┤        ├─────────────────────┤        ├───────────────────────────────┤
│ Memory Mapped / Shared Libs   │        │ Frame 312 (Kernel)  │        │ Memory Mapped / Shared Libs   │
├───────────────────────────────┤        ├─────────────────────┤        ├───────────────────────────────┤
│ Heap (malloc / new)           │───────>│ Frame 450 (Page B)  │<───────│ Heap (malloc / new)           │
├───────────────────────────────┤        ├─────────────────────┤        ├───────────────────────────────┤
│ .bss (uninitialized globals)  │        │ Frame 891 (Shared)  │<───────│ Shared Memory (mmap)          │
├───────────────────────────────┤        └─────────────────────┘        └───────────────────────────────┘
│ .data (initialized globals)   │                   ▲
├───────────────────────────────┤                   │
│ .text (machine instructions)  │                   └── Hardware MMU translates addresses
└───────────────────────────────┘                       via Page Table Entries (PTEs)
```

The CPU hardware has a dedicated chip called the **MMU (Memory Management Unit)**. Every time your program reads a pointer, the MMU consults the process's **Page Table** to translate the virtual address into a physical page frame.

Do this: Create `layout.c` to inspect where your process places different variables in its virtual address space:

```c
/* layout.c */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int global_initialized = 42;       /* Lives in .data segment (binary on disk) */
int global_uninitialized;          /* Lives in .bss segment (zeroed at launch) */

void print_layout(void) {
  int stack_variable = 7;          /* Lives on the stack (grows downwards)    */
  void *heap_variable = malloc(64);/* Lives on the heap (grows upwards)      */

  printf("=== Virtual Address Space Layout (PID: %d) ===\n", getpid());
  printf("Code (.text) function ptr : %p\n", (void *)&print_layout);
  printf("Initialized Data (.data)  : %p\n", (void *)&global_initialized);
  printf("Uninitialized Data (.bss) : %p\n", (void *)&global_uninitialized);
  printf("Heap (malloc)             : %p\n", heap_variable);
  printf("Stack (local variable)    : %p\n", (void *)&stack_variable);

  free(heap_variable);
}

int main(void) {
  print_layout();
  return 0;
}
```

  title="Compile and inspect virtual address space"
  cmd={`gcc -std=c11 -Wall -Wextra layout.c -o layout && ./layout`}
  expect={`=== Virtual Address Space Layout (PID: 12345) ===
Code (.text) function ptr : 0x55a1b2c3d149
Initialized Data (.data)  : 0x55a1b2c40020

<WhyItWorked>
Notice how the addresses are ordered in virtual memory:
1. `.text` (Code) sits at lower addresses (`0x55...d149`).
2. `.data` and `.bss` sit right above code (`0x55...0020`).
3. The **Heap** sits above global variables and expands *upward* as you call `malloc`.
4. The **Stack** sits near the very top of user space (`0x7ffe...`) and expands *downward* as functions call other functions!
</WhyItWorked>

## 2. Process Creation: fork() + execve()

In Linux and Android, processes are never created from scratch; they are **cloned** from an existing parent process via `fork()`, and then optionally transformed via `execve()`.

<ConceptComparison
  title="Process & Execution Primitives in Linux"
  leftHeader="fork()"
  rightHeader="execve()"
  rows={[
    {
      feature: 'Action',
      left: 'Duplicates the calling process. After fork(), two processes execute identical code.',
      right: 'Replaces current process memory with a brand-new executable loaded from disk.',
    },
    {
      feature: 'Return Behavior',
      left: 'Returns TWICE: returns child PID in parent, returns 0 in child, returns -1 on error.',
      right: 'Never returns on success (the entire old program is overwritten and gone).',
    },
    {
      feature: 'PID & Resources',
      left: 'Creates a new PID. Clones file descriptors and page table references.',
      right: 'Preserves the same PID and open file descriptors, but clears stack, heap, and registers.',
    },
    {
      feature: 'AOSP Usage',
      left: 'Zygote forks to create every new Android app process.',
      right: 'init daemon runs execve() to launch native system daemons (logd, vold, netd).',
    },
  ]}
/>

Do this: Create `forker.c` to spawn a child process that executes `/bin/echo`:

```c
/* forker.c */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
  printf("Parent process starting (PID: %d)...\n", getpid());

  pid_t pid = fork();

  if (pid < 0) {
    perror("fork failed");
    return 1;
  }

  if (pid == 0) {
    // -------------------------------------------------------------
    // CHILD PROCESS: fork() returned 0
    // -------------------------------------------------------------
    printf("Child process active (PID: %d, Parent PID: %d)\n", getpid(), getppid());
    
    // Replace child's image with /bin/echo
    char *args[] = {"echo", "Hello from child process!", NULL};
    char *env[] = {NULL};
    
    execve("/bin/echo", args, env);

    // If execve returns, it MUST have failed!
    perror("execve failed");
    _exit(127);
  } else {
    // -------------------------------------------------------------
    // PARENT PROCESS: fork() returned the child's PID
    // -------------------------------------------------------------
    printf("Parent waiting for child (PID: %d) to finish...\n", pid);
    
    int status = 0;
    waitpid(pid, &status, 0); // Reaps zombie child process

    if (WIFEXITED(status)) {
      printf("Parent: Child exited normally with return code %d\n", WEXITSTATUS(status));
    }
  }

  return 0;
}
```

<DeepDive title="Copy-on-Write (COW): How Android Launches Apps in 5ms">
If `fork()` had to copy all 200MB of Android framework libraries and preloaded classes from RAM every time you tapped an app icon, launching an app would freeze your phone for 1-2 seconds.

Instead, Linux uses **Copy-on-Write (COW)**:
1. When `fork()` is called, the kernel **only copies the Page Table entries** (pointers to physical frames), NOT the physical RAM pages themselves.
2. The kernel marks all shared physical frames as **Read-Only** in both parent and child page tables.
3. If both processes only *read* memory, zero memory copying ever takes place!
4. The instant either process tries to *write* to a variable, the CPU hardware raises a **Page Fault Exception**.
5. The kernel catches the page fault, allocates **one single new 4KB physical frame**, copies just that 4KB page, updates the faulting process's page table to point to the new frame, marks it writable, and resumes execution seamlessly.

This is why Android's **Zygote** process pre-loads all common Android Java classes at boot: every app inherits them instantly via COW!
</DeepDive>

## 3. Inter-Process Communication: POSIX Shared Memory

Because processes have completely isolated virtual address spaces, passing a raw pointer like `0x7ffee400` between processes over a pipe will crash with a segmentation fault.

To share high-speed data (like camera video frames, audio buffers, or sensor streams), processes ask the Linux kernel to map the **same physical RAM frames into both of their virtual address spaces**.

Do this: Create a shared memory producer (`shm_producer.c`) and consumer (`shm_consumer.c`).

```c
/* shm_producer.c */
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>
#include <sys/stat.h>

#define SHM_NAME "/aosp_mastery_shm"
#define SHM_SIZE 4096

struct SensorPayload {
  int sensor_id;
  int sample_count;
  float temperature;
  char message[64];
};

int main(void) {
  // 1. Create a POSIX shared memory file descriptor
  int fd = shm_open(SHM_NAME, O_CREAT | O_RDWR, 0660);
  if (fd < 0) { perror("shm_open"); return 1; }

  // 2. Newly created shm has 0 bytes length; truncate it to 4KB!
  if (ftruncate(fd, SHM_SIZE) < 0) { perror("ftruncate"); return 1; }

  // 3. Map shared memory into our virtual address space
  struct SensorPayload *data = mmap(NULL, SHM_SIZE, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
  if (data == MAP_FAILED) { perror("mmap"); return 1; }

  // 4. Write sensor data into shared RAM
  data->sensor_id = 42;
  data->sample_count = 1000;
  data->temperature = 36.6f;
  strncpy(data->message, "AOSP Sensor Spine Active", sizeof(data->message));

  printf("Producer: Wrote sensor sample (ID: %d, Temp: %.1fC) to shared memory.\n",
         data->sensor_id, data->temperature);

  munmap(data, SHM_SIZE);
  close(fd);
  return 0;
}
```

Now write the consumer (`shm_consumer.c`):

```c
/* shm_consumer.c */
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>

#define SHM_NAME "/aosp_mastery_shm"
#define SHM_SIZE 4096

struct SensorPayload {
  int sensor_id;
  int sample_count;
  float temperature;
  char message[64];
};

int main(void) {
  // 1. Open the existing shared memory object read-only
  int fd = shm_open(SHM_NAME, O_RDONLY, 0660);
  if (fd < 0) { perror("shm_open failed (did producer run?)"); return 1; }

  // 2. Map into consumer virtual address space
  struct SensorPayload *data = mmap(NULL, SHM_SIZE, PROT_READ, MAP_SHARED, fd, 0);
  if (data == MAP_FAILED) { perror("mmap"); return 1; }

  // 3. Read data produced by the other process
  printf("Consumer: Read from shared memory:\n");
  printf("  Sensor ID    : %d\n", data->sensor_id);
  printf("  Sample Count : %d\n", data->sample_count);
  printf("  Temperature  : %.1f C\n", data->temperature);
  printf("  Message      : %s\n", data->message);

  munmap(data, SHM_SIZE);
  close(fd);
  
  // Clean up shm node
  shm_unlink(SHM_NAME);
  return 0;
}
```

## 4. Cross-Compilation: Building for ARM64 (aarch64)

Most Android smartphones and Cuttlefish ARM64 virtual devices run on the 64-bit ARM architecture (`aarch64`), while development workstations run on x86_64 Intel/AMD processors.

When compiling code for a different architecture than the one you are running on, you use a **Cross-Compiler**.

```text
Host Architecture (x86_64 Workstation)               Target Architecture (ARM64 Device)
┌───────────────────────────────────────┐            ┌───────────────────────────────────┐
│ Host Compiler: gcc / clang            │            │ Android Phone / Cuttlefish ARM64  │
│ Generates: x86_64 machine code        │            │ Executes: ARM64 instructions      │
├───────────────────────────────────────┤            └───────────────────────────────────┘
│ Cross-Compiler: aarch64-linux-gnu-gcc │                              ▲
│ Generates: ARM64 machine code ────────┼──────────────────────────────┘
└───────────────────────────────────────┘
```

Do this: Compile your layout program for ARM64:

```bash
aarch64-linux-gnu-gcc -std=c11 -Wall -Wextra layout.c -o layout_arm64
```

Verify with `file` that the resulting ELF binary was compiled for ARM64:

<TestRunner

## 5. System Call Tracing with strace

How do you know what a program is doing when you don't have its source code or a debugger? You intercept its **system calls**.

`strace` uses the Linux kernel's `ptrace(2)` system call to pause the target process on every entry and exit from kernel mode, printing the arguments and return values.

Do this: Trace the exact system calls executed by your `forker` program:

<TestRunner
  title="Trace clone, execve, and wait4 syscalls"
  cmd={`strace -f -e trace=clone,execve,wait4 ./forker`}
  expect={`execve("./forker", ["./forker"], 0x7ffd...) = 0
Parent process starting (PID: ...)
clone(child_stack=NULL, flags=CLONE_CHILD_CLEARTID|CLONE_CHILD_SETTID|SIGCHLD, ...) = 12348
[pid 12348] Child process active (PID: 12348, Parent PID: 12347)
[pid 12347] Parent waiting for child (PID: 12348) to finish...
[pid 12348] execve("/bin/echo", ["echo", "Hello from child process!"], NULL) = 0
[pid 12348] +++ exited with 0 +++
[pid 12347] wait4(12348, [{WIFEXITED(s) && WEXITSTATUS(s) == 0}], 0, NULL) = 12348
Parent: Child exited normally with return code 0
+++ exited with 0 +++`}
/>

<WhyItWorked>
Notice what happened at the kernel level:
1. `clone(...) = 12348`: The parent invoked the Linux `clone` syscall (the kernel underlying `fork()`), which returned child PID 12348.
2. `execve("/bin/echo", ...)`: Child process 12348 replaced its virtual memory space with `/bin/echo`.
3. `wait4(12348, ...)`: Parent process paused execution until child 12348 terminated.
</WhyItWorked>
