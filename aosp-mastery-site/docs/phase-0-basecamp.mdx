<DidYouKnow title="Why Google Built 'repo' Instead of Using Git Submodules">
  In 2008, when Google open-sourced Android, Git submodules were primitive and recorded hard-coded commit SHAs inside a parent repository.
  <br /><br />
  <strong>The Problem:</strong> AOSP is not one giant repository (monorepo); it is over <strong>1,000 independent Git repositories</strong> (Linux kernel forks, hardware HALs, Bionic libc, ART runtime, frameworks). Updating a single milestone branch using Git submodules would have required making 1,000 individual commits in a parent repo just to update the commit hashes!
  <br /><br />
  <strong>The Solution:</strong> Google wrote <code>repo</code> in Python. Instead of nested submodules, <code>repo</code> reads a single XML manifest (<code>default.xml</code>). When Google wants to tag or branch all 1,000 repositories, they change just one XML file.
  <br /><br />
  <strong>Pro-tip:</strong> When syncing on unstable or slow internet connections, always pass <code>--no-clone-bundle</code>. By default, repo tries to download pre-packaged tarballs from Google Cloud Storage, which frequently times out or disconnects on strict corporate and university networks.
</DidYouKnow>

## 3. Hardware Self-Check (Automated Gate)

Execute these checks in your terminal. Every condition must pass before proceeding:

<TestRunner
  title="Hardware / OS Self-Check"
  cmd={`# 1. Host Architecture & glibc (need 64-bit x86_64, glibc >= 2.17)
uname -m && ldd --version | head -n1

# 2. Disk Storage (need >= 400 GB free where you will checkout and build)
df -h . | awk 'NR==2{print "Free disk: "$4}'

# 3. Memory (need >= 64 GB RAM or 32GB RAM + 32GB Swap)
free -h | awk 'NR==2{print "Total RAM: "$2}'

# 4. Hardware Virtualization Extensions (for Cuttlefish KVM)
grep -c -w "vmx\\|svm" /proc/cpuinfo`}
  expect={`x86_64
ldd (Ubuntu GLIBC 2.35) 2.35
Free disk: 512G
Total RAM: 64G
16

(Confirm every check passes. A non-zero virtualization count proves KVM support.)`}
/>

<WhyItWorked>
A full AOSP checkout consumes ~250 GB of disk space. A single userdebug build generates an additional ~150 GB of intermediate object files and disk images in `out/`. Furthermore, Soong and Ninja link massive binaries (such as `libandroid_runtime.so` and `system_server`) concurrently; compiling with fewer than 64 GB of combined RAM will trigger the Linux kernel Out-Of-Memory (OOM) killer, aborting the build hours into the process.
</WhyItWorked>

### Cuttlefish Host Packages & KVM Permissions

Install the host packages required to run Cuttlefish:

```bash
# 1. Install build utilities
sudo apt install -y git devscripts equivs config-package-dev debhelper-compat golang curl

# 2. Clone and build Cuttlefish host packages
git clone https://github.com/google/android-cuttlefish
cd android-cuttlefish
tools/buildutils/build_packages.sh

# 3. Install Debian packages
sudo dpkg -i ./cuttlefish-base_*_*64.deb || sudo apt-get install -f -y
sudo dpkg -i ./cuttlefish-user_*_*64.deb || sudo apt-get install -f -y

# 4. Add your user account to the required virtualization groups
sudo usermod -aG kvm,cvdnetwork,render $USER

# 5. REBOOT to activate group memberships
sudo reboot
```

:::warning Reboot Required
Linux user group changes do not take effect in existing terminal sessions. You must reboot your machine. After rebooting, run `groups` and verify that `kvm`, `cvdnetwork`, and `render` appear in the output.
:::

## 5. Synchronizing the Source Code

Initialize your local tree and synchronize repositories:

```bash
mkdir aosp && cd aosp

# 1. Initialize repo with the stable release manifest
repo init -u https://android.googlesource.com/platform/manifest -b android-latest-release

# 2. Synchronize the codebase (download ~100GB of git packfiles)
repo sync -c -j$(nproc) --no-clone-bundle
```

<WhyItWorked>
- `-c` (current branch): Tells Repo to fetch only the specific branch pinned in the manifest rather than all historical Git branches, cutting download volume by more than 50%.
- `--no-clone-bundle`: Bypasses Google's pre-packaged HTTP clone bundles if your network connection experiences socket drops or CDN throttling.
</WhyItWorked>

## 6. Anatomy of the AOSP Source Tree

AOSP is organized into functional layers. Memorize where subsystems reside:

<DeepDive title="Anatomy of the Top-Level AOSP Tree">
```
aosp/
├── art/                 # Android Runtime: garbage collector, JIT/AOT compiler, dex2oat
├── bionic/              # Android's C library (libc), math library (libm), dynamic linker
├── bootable/            # Recovery system and bootloader reference code
├── build/
│   ├── soong/           # The Soong build system engine (converts Android.bp -> Ninja)
│   └── make/            # Core build logic, envsetup.sh, and lunch target definitions
├── cts/                 # Compatibility Test Suite (CTS) test modules
├── device/              # Board support configurations (e.g. device/google/cuttlefish)
├── frameworks/
│   ├── base/            # The Java framework: system_server, ActivityManager, WindowManager
│   └── native/          # Native platform services: SurfaceFlinger, libgui, libbinder
├── hardware/
│   ├── interfaces/      # Hardware Abstraction Layer AIDL/HIDL interface specifications
│   └── libhardware/     # Legacy legacy HAL shared library headers
├── kernel/              # Prebuilt kernel binaries and Kleaf kernel build integration
├── packages/            # Built-in Android apps (Settings, Launcher3, SystemUI)
├── system/
│   ├── core/            # Low-level native utilities: init (PID 1), logd, debuggerd, adb
│   ├── sepolicy/        # Core platform SELinux policy rules (.te)
│   └── bpf/             # Extended Berkeley Packet Filter network monitoring engine
└── tools/               # Host developer tools, Trade Federation (tradefed), ATest
```
</DeepDive>
