## 4. Installing the Gerrit `commit-msg` Hook

Before making any commits, install the official Google Gerrit hook so the `Change-Id` is appended automatically:

<TestRunner
  title="Install Gerrit commit-msg Hook"
  cmd={`# Navigate to project git directory
cd frameworks/base

# Install the official hook
curl -Lo .git/hooks/commit-msg \\
  https://android-review.googlesource.com/tools/hooks/commit-msg
chmod +x .git/hooks/commit-msg

# Verify hook is active on commit
git commit --amend --no-edit
git log -1 --format=%B | grep "Change-Id:"`}
  expect={`Change-Id: I42a98f1234567890abcdef1234567890abcdef12`}
/>

## 5. Uploading and Iterating on Gerrit

The iteration cycle for an AOSP engineer:

```
  +------------------+
  |  Edit Code       |
  +--------+---------+
           |
           v
  +------------------+
  | git commit --amend  <-- (Preserves Change-Id!)
  +--------+---------+
           |
           v
  +------------------+
  |  repo upload .   |  --> Pushes new Patch Set to existing Gerrit Change
  +--------+---------+
           |
           v
  +------------------+
  | Reviewer Feedback|
  |  (Address lines) |
  +--------+---------+
           |
           +----------------> Repeat until Code-Review +2 and Verified +1
```

## 6. Navigating Unfamiliar Code with `cs.android.com`

Before modifying unfamiliar platform services, use `cs.android.com` to explore references and history:

<DeepDive title="Pro Tips for AOSP Code Search (cs.android.com)">
1. **Symbol Search:** Type `class:FooService` or `def:FooService` to jump directly to class and function definitions.
2. **Path Filtering:** Use `file:^frameworks/base/` to restrict results to the framework layer.
3. **Cross-References:** Click any function name in the web UI to see **Callers** (functions that call this method) and **Overridden by** (child classes).
4. **Git Blame to Gerrit:** Click any line number and select **History** $\rightarrow$ it directly opens the exact Gerrit review, code comments, and reviewer discussions that created that line of code!
</DeepDive>

## 7. The AOSP Maintainer's Review Checklist

Run this self-review checklist before typing `repo upload`:

- [ ] **One Logical Change:** Does this patch do exactly one thing? (Unrelated cosmetic edits or whitespace changes stripped).
- [ ] **Imperative Subject:** Does the first line use imperative present tense (`Fix`, `Add`, `Remove`)?
- [ ] **Line Wrapping:** Is the commit body wrapped strictly at 72 columns?
- [ ] **Test Coverage:** Does the `Test:` line describe executable commands (`atest`, `Cts...`)?
- [ ] **Change-Id:** Is a valid `Change-Id:` present in the footer?
- [ ] **Linear History:** Rebased cleanly onto the target branch without merge commits (`git rebase aosp/main`)?
- [ ] **SELinux / Architecture:** Are new interfaces annotated with `@VintfStability` and covered by proper `.te` policy?

## Mastery Check

The bar: a **perfectly formatted, self-reviewed patch series uploaded to Gerrit and passing a maintainer's checklist**:

- Configured the Gerrit `commit-msg` hook and generated valid `Change-Id` footers.
- Authored a multi-line commit message with imperative summary, body rationale, and mandatory `Test:` tags.
- Uploaded the patch set using `repo upload`.
- Successfully amended the commit (`git commit --amend`) and uploaded Patch Set 2.
- Verified compliance against the AOSP maintainer's review checklist.

**Spine artifact:** Commit the formatted patch series, commit messages, and Gerrit review transcript under `spine/14-patch-series`.
